# Картотека граждан

Небольшое React-приложение с дашбордом и картотекой граждан. Данные тестовые, приложение имитирует работу с API через MSW.

## Запуск

Нужны Node.js 20+ и npm.

```bash
npm install
npm run dev
```

Для проверки сборки:

```bash
npm run build
```

## Что реализовано

- **Дашборд:** общее количество граждан, основные показатели и распределения по статусам, городам, категориям и годам регистрации.
- **Картотека:** поиск по ФИО, фильтры по городу, статусу и полу, счётчик найденных записей.
- **Список граждан:** виртуализация строк и постраничная догрузка при прокрутке.
- **Карточка гражданина:** разделы с личными данными, документами, адресом, образованием и родственниками; редактирование и сохранение полей.
- **Состояния запросов:** загрузка и сообщения об ошибках.

## Стек

React 18, TypeScript, Vite, Tailwind CSS 4, TanStack Query, MSW, Recharts.

## Структура

Код разделён по слоям Feature-Sliced Design:

```text
src/
  app/       # запуск, провайдер запросов, MSW, стили
  pages/     # дашборд и картотека
  widgets/   # список, карточка и боковая навигация
  features/  # фильтры граждан
  entities/  # модель гражданина, API и запросы
  shared/    # общие UI-компоненты и утилиты
```

Поля карточки и разделы описаны в `src/widgets/citizen-card/model/formSchema.ts`. Конфигурации колонок и показателей находятся рядом с компонентами, которые их используют.

## Как работают данные

При запуске включается MSW. Обработчики запросов находятся в `src/app/mocks/handlers.ts`, генерация тестовых записей — в `src/app/mocks/citizenDb.ts`.

В картотеке используется набор из **100 000 детерминированно генерируемых граждан**. Клиент запрашивает записи порциями по 100, а виртуализация отображает только видимую часть списка. Поиск по ФИО отправляется с задержкой 300 мс после ввода.

Редактирование выполняется через `PATCH /api/citizens/:id`. **Изменения сохраняются только в памяти текущего сеанса MSW и теряются при перезагрузке страницы**: настоящей базы данных в проекте нет.

## Ограничения демоверсии

- API и данные имитируются в браузере; для реального использования нужен backend.
- После изменения полей, используемых в фильтрах, результаты поиска в текущей реализации могут не соответствовать изменённым значениям: фильтрация выполняется по исходным тестовым данным.
- Полноценная валидация персональных и документных полей пока не реализована.
- Автоматические тесты в проект не добавлены.

## Возможные улучшения

В первую очередь — согласовать редактирование с фильтрацией и статистикой, обновлять выбранную карточку после сохранения и добавить проверку значений в API. Затем — тесты на фильтры и сохранение, более строгую типизацию редактируемых полей и обработку ошибок догрузки.
