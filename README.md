# Картотека граждан

Небольшое React-приложение с дашбордом и картотекой граждан. Данные тестовые, приложение имитирует работу с API через MSW.

## Запуск

Нужны Node.js 20+ и npm.

```bash
npm install
npm run dev
```

Для проверки сборки:

```bash
npm run build
```

## Что реализовано

- **Дашборд:** общее количество граждан, основные показатели и распределения по статусам, городам, категориям и годам регистрации.
- **Картотека:** поиск по ФИО, фильтры по городу, статусу и полу, счётчик найденных записей.
- **Список граждан:** виртуализация строк и постраничная догрузка при прокрутке.
- **Карточка гражданина:** разделы с личными данными, документами, адресом, образованием и родственниками; редактирование и сохранение полей, включая изменение статуса; валидация через Zod.
- **Управление родственниками:** поиск и добавление гражданина из картотеки, выбор степени родства, удаление семейной связи и переход в карточку родственника.
- **Состояния запросов:** загрузка, блокировка действий во время сохранения и сообщения об ошибках.

## Стек

React 18, TypeScript, Vite, Tailwind CSS 4, TanStack Query, Zod, MSW, Recharts.

## Структура

Код разделён по слоям Feature-Sliced Design:

```text
src/
  app/       # запуск, провайдер запросов, MSW, стили
  pages/     # дашборд и картотека
  widgets/   # список, карточка и боковая навигация
  features/  # фильтры граждан
  entities/  # модель гражданина, API и запросы
  shared/    # общие UI-компоненты и утилиты
```

Поля карточки и разделы описаны в `src/widgets/citizen-card/model/formConfig.ts`, валидация — в `validationSchema.ts`. Конфигурации колонок и показателей находятся рядом с компонентами, которые их используют.

## Как работают данные

При запуске включается MSW. Обработчики запросов находятся в `src/app/mocks/handlers.ts`, генерация тестовых записей — в `src/app/mocks/citizenDb.ts`.

В картотеке используется набор из **100 000 детерминированно генерируемых граждан**. Клиент запрашивает записи порциями по 100, а виртуализация отображает только видимую часть списка. Поиск по ФИО отправляется с задержкой 300 мс после ввода.

Редактирование выполняется через `PATCH /api/citizens/:id`. Перед сохранением поля проверяются с помощью Zod. Изменения учитываются при последующей фильтрации и расчёте статистики.

Семейные связи создаются и удаляются через API, имитируемый MSW. Родственники выбираются из существующих записей по ID, а удаление связи не удаляет самого гражданина.

**Изменения сохраняются только в памяти текущего сеанса MSW и теряются при перезагрузке страницы**: настоящей базы данных в проекте нет.

## Ограничения демоверсии

- API и данные имитируются в браузере; для реального использования нужен backend.
- Изменения граждан и семейных связей не сохраняются после перезагрузки страницы.
- Семейные связи не создаются автоматически в обратном направлении.
- Поиск родственников ограничен первыми 20 совпадениями, исключение уже добавленных родственников выполняется на клиенте.
- Добавление и удаление родственников применяются сразу и не откатываются кнопкой «Отмена» основной формы.
- Серверная валидация данных не реализована.
- Автоматические тесты в проект не добавлены.

## Возможные улучшения

В первую очередь — добавить серверную валидацию, обработку ошибок догрузки и тесты на фильтры, редактирование и семейные связи. Затем — реализовать двусторонние связи родственников, серверную фильтрацию кандидатов и постоянное хранение данных.
